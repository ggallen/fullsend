# PR #8313 review run audit

Source: [PR #8313](https://github.com/fullsend-ai/fullsend/pull/8313), its review comments and [sticky review comment](https://github.com/fullsend-ai/fullsend/pull/8313#issuecomment-6101774685) edit history. Historical review heads were fetched and inspected read only.

## Totals and interpretation

- 49 completed review runs; **$195.25** of reported review model cost. The associated fix status comments report **$44.06** of model cost.
- 122 distinct finding IDs from inline comments, review bodies, and embedded review metadata. IDs can represent multiple descriptions of one root cause; some are advisory or later reclassified.
- 87 items have an earlier assessed run, including 39 findings whose tentative anchor was checked against historical behavior. This is an item count, not a count of distinct root causes or avoidable runs.
- 26 finding IDs were carried open at least once, for 40 item-run carryovers.
- `open carryover` counts later runs that reposted the ID or marked it `open` in the review metadata. `historical context` counts later metadata snapshots containing the ID, including resolved or reclassified history; it is **not** an unresolved count.
- `earliest possible` records the earliest reviewed head where the described behavior was found. For the 42 previously tentative items, the `assessment_evidence` column in the item CSV now states the behavior checked in that head. `first evidenced` means no earlier reviewed head was substantiated by the examined path; it is not proof that no earlier issue existed.
- Review snapshots retain only the latest five runs in the visible sticky comment, but GitHub comment edit history supplies all 49 full snapshots.

## Earlier-detection examples

- [Version 2 rotation state](https://github.com/fullsend-ai/fullsend/pull/8313#discussion_r4244457023): first raised on run 32, but the writer and version constant are present in run 1. This was an intentional breaking change, so it is a missed discussion opportunity rather than a confirmed defect.
- [Status treating an outside-inventory supplied PAT as healthy](https://github.com/fullsend-ai/fullsend/pull/8313#pullrequestreview-5486305470): raised on run 32; the historical enrollment proof path was already present on run 1. The later verifier callback made a direct check easier.
- [Missing verifier on minted replacement credentials](https://github.com/fullsend-ai/fullsend/pull/8313#discussion_r4252894140): raised on run 43 and carried through runs 44–48; both creation paths already skipped verification on a nil callback in run 1. The fix agent disagreed while the reviewer classified it as optional because the live constructor sets the callback, then added fail-closed guards after later reviews.
- [Status drift after a deleted historical managed account](https://github.com/fullsend-ai/fullsend/pull/8313#pullrequestreview-5497728586): raised on run 46; the exact successful supplied-recovery scenario was enabled around run 45, so this is a short discovery lag, not a run-1 miss.
- [Malformed expiry bypass](https://github.com/fullsend-ai/fullsend/pull/8313#discussion_r4253656142): raised on run 45 after the new health-based skip was added in that same review head. An earlier review could not report this exact defect.

## Practical conclusion

Large discovery lags coexist with fix introduced regressions. For example, the version 2 migration, outside-inventory status handling, missing verifier guard, and several documentation errors were present in early reviewed heads, while the malformed expiry bypass and in flight managed account filter arose from late fixes. The $195.25 total is observable; exact savings from perfect earlier detection cannot be derived by subtracting runs because each fix changes the code to be reviewed.
